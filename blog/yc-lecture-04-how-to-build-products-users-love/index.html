如何打造用户热爱的产品

YC 创业课 2026年6月27日

根据 YC《如何创办初创公司》系列课程第七讲整理 讲者：Kevin Hale（Wufoo 联合创始人、YC 合伙人）

一、关于这次分享

大家好。当我谈”打造用户热爱的产品”时，我具体指的是：我们如何做出拥有狂热用户群体的东西，让用户无条件希望我们的产品和公司成功？

今天的信息量会很大。尽量少做笔记，主要用耳朵听。幻灯片链接稍后会发在我的 Twitter 账号上，你们可以在上面标注问题，如果现场没时间回答，我会在会后回复。

二、增长的真相：转化率与流失率

过去几周你们听了很多关于增长的内容。在我看来，增长其实很简单。它就是两个概念（或者说变量）的交互：

转化率和流失率。

两者的差距，基本上决定了你增长的速度。

但大多数人和典型的商业思维者，倾向于用数学的、计算的方式来看待这种交互。今天我想在更人性化的尺度上讨论这些问题。因为在初创公司的早期阶段，你和用户之间的互动是相当亲密的——我认为在打造产品时，有一种不同的视角来看待这些事情。我们会看很多不同的例子，看这件事情如何被出色地执行。

我教初创公司很多东西背后的哲学是：达到 10 亿美元的 best way，是专注于帮你赚到第一美元、获得第一个用户的那些价值观。如果你把这件事做对了，其他一切都会水到渠成。 这是一种信念。

三、Wufoo 的故事

我是通过 YC 校友的身份成为 YC 合伙人的。我参加了 2006 年冬季批次（那是 YC 举办的第二期），我做了一款叫 Wufoo 的产品。

Wufoo 是一个在线表单构建器，帮你创建联系表单、在线调查和简单的支付表单。它本质上是一个数据库应用，但看起来像 Fisher-Price（费雪玩具）设计的。

有意思的是，因为它非常好用，我们的客户覆盖了你能想到的每一个行业市场和垂直领域，包括大多数《财富》500 强公司。

我经营了这家公司五年，然后在 2011 年被 SurveyMonkey 收购。当时这是一笔非常有趣的收购案例。我们当时只有 10 个人，虽然通过 YC 在硅谷融了资，但我们实际上是从佛罗里达州远程经营这家公司的。我们没有办公室，所有人都在家工作，是一个有趣的异类。

（展示 PPT 幻灯片）这里每一个点代表一家通过 IPO 或收购退出的初创公司，我们是左边那个离群值。横轴代表融资金额，纵轴代表退出时的估值。

总结一下：平均而言，一家初创公司融资约 2500 万美元，给投资者的回报约为 676%。而 Wufoo 总共只融了约 11.8 万美元，给投资者的回报约为 29,561%。

四、Wufoo 与众不同的秘密

很多人好奇是什么让 Wufoo 有点不一样，或者我们如何以不同的方式经营公司。答案很大程度上聚焦于产品。

我们不感兴趣做那种”人们只是想用”的软件——那种让你想起自己在格子间里工作的东西，因为它本质上是一个数据库应用。我们想要的，是人们想要热爱的产品，人们想要与之建立关系的产品。

我们对这个理念的执着程度，几乎到了科学化的地步。我们当时说：“初创公司有意思的地方在于，我们想要创造人们热爱的东西——而爱和无条件的情感，在现实生活中是很难做到的事情。在初创公司里，我们必须在规模化的情况下做到这件事。” 所以我们决定从这个问题开始：

“现实世界中的关系是怎样运作的，我们如何把它们应用到经营业务和打造产品的方式中？”

我们会讨论两个隐喻：把获取新用户当作约会，把留住现有用户当作一段成功的婚姻。

五、约会隐喻：第一印象的力量

在约会这件事上，我们发现的很多东西都与第一印象有关。

你们所有人经常谈论你们关系中的”起源故事”。你们会告诉我你们的初吻、如何相识、如何求婚。这些东西你们翻来覆去地讲，基本上就是关系的口碑故事。我们在公司做类似的事情。人类是”关系制造”生物。我们忍不住要创造我们反复互动的东西，并赋予它们人格——无论我们开的是什么车、穿的是什么衣服、用的是什么工具和软件，我们最终都会赋予它特征、个性，并期望它以某种方式表现。这就是我们与之互动的方式。

第一印象对任何关系的开始都很重要，因为这是我们会反复讲述的那个故事，对吧？ 起源故事有一种特殊的分量。

让我举一个例子。如果你和某人第一次约会，一起吃了一顿不错的晚餐，但你发现他们在挖鼻孔，你可能不会再约第二次了。但如果你和某人结婚 20 到 30 年，发现他们在沙发上挖鼻孔，你不会立即打电话给律师说：“我们有麻烦了，你得开始起草离婚文件了。” 你会耸耸肩说：“至少他心地善良。”

所以，第一次互动的阈值要低得多——成还是败，就这一次。

在软件和大多数互联网产品中，第一印象是很明显的，你会发现很多公司在营销人员负责的事情上很用心。但我的论点是：善于做产品的人，会发现很多其他的时刻，并让它们变得难忘——你收到的第一封邮件、你第一次登录时发生的事情、那些链接、那些广告、你第一次联系客户支持时。所有这些，都是诱惑的机会。

六、如何打造”第一时刻”：两种质量

我们实际上从日本人那里借来了这个概念。他们实际上有两个词来描述”完成一件东西时，如何判断它是否高质量”。这两个”质量”的词是：

  • Atarimae hinshitsu（理所当然的质量）：基本上指功能性。
  • Miryokuteki hinshitsu（迷人的质量）： enchanting quality，迷人的质量。

以一支笔为例。如果这支笔的重量、墨水流动的方式、以及别人看到你的笔迹时的感受，对用户和使用笔的副产品体验者来说都是愉悦的，那它就具有 miryokuteki——把事情提升到了下一个层次。

让我们从一些例子开始。

例子一：Wufoo 的登录链接

这是 Wufoo 的登录链接，上面有一只恐龙——我觉得这太棒了！但如果你把鼠标悬停上去，除了登录工具提示之外，它还会显示”RARRR！“（恐龙的吼声）。我们在早期可用性测试阶段注意到，这会让人们脸上浮现微笑——毫不夸张地说，是普遍现象。我认为很多时候我们在评估产品时，从来不会想：“嘿，当这个人和这个东西互动时，他脸上的情绪是什么？“

例子二：Vimeo 的启动页面

这是 Vimeo 的启动页面（是几个迭代之前的版本，我觉得是最美的那个）。它让你知道，当你开始和他们一起踏上这段旅程时，这将是一件不同的事情——他们在整个网站上都这样做。如果你搜索”fart”（放屁）这个词，当你上下滚动时，它会发出放屁的声音。有一种不同的感觉，这个网站在和你互动，它有点神奇，有点不同。这是你想谈论的事情。

例子三：Cork’d 的注册表单

你不一定要通过设计来做到这一点。这是 Cork’d 的注册表单——这是一个曾经存在的葡萄酒爱好者社交网络。表单上写着：

  • 电子邮件地址——也是你的登录名，必须是真实的。
  • 名字——你妈妈怎么叫你。
  • 姓氏——你的战友怎么叫你。
  • 密码——你能记住但别人很难猜到的。
  • 密码确认——再输一次，就当是考试。

填这个表单基本上像在读一首诗。这种感受会让你想：“哦，我喜欢背后做这个产品的人，我会享受这段体验的。” 现在想想，填这样的表单，说明了他们的个性是什么样的？而让我失望的是，雅虎强迫旗下所有产品和服务使用完全一样的登录表单。

例子四：Flickr 的召唤行动

Flickr 的召唤行动（Call to Action）是我认为最好的之一：“Get in there！“（进来吧！）

例子五：Heroku 的注册页面

这是 Heroku 的注册页面（可能是旧版本）。它的出色之处在于，让你开始感受到——扩展后端服务就像上下拖动不同的旋钮和滑块一样简单。它看起来相当容易扩展。

例子六：Chocolat 代码编辑器

这是给满屋子的计算机科学人看的，我想你们会欣赏这个。这是 Chocolat，一个代码编辑器。他们只有一个召唤行动：当试用期结束时，所有功能都一样，除了我们把字体改成了 Comic Sans（ Comic Sans 字体）。他们基本上在说：“嘿，我们知道我们的用户是谁，我们真正的客户是谁。是那些在乎这件事的人。“

例子七：Hurl 的 404 页面

这是 Hurl——一个用于检查 HTTP 请求的网站。有时候出错的地方，也是”第一时刻”的机会。如果你遇到 404 错误，你会看到这个：（一只独角兽在吐彩虹。）

例子八：MailChimp 的帮助文档

我们经常做的事情是：做出非常漂亮的营销材料，但当你真正需要文档时，我们在设计和功能上偷工减料。这种事情一遍又一遍地发生。MailChimp 是把这件事做对的公司。他们重新设计了所有的帮助指南，让它们看起来像杂志封面。结果，这些功能的阅读量一夜之间大幅上升，而关于帮助人们优化邮件的这些功能的客户支持量下降了。

例子九：Stripe 的文档

说到文档，Stripe——有意思的是，作为一家 API 公司，它实际上没有用户界面。用户体验基本上就是文档。在文档中也有机会去迷住和震撼用户。我喜欢他们的一件事是：他们的例子很棒，但如果你登录到应用里，大多数人的 API 最痛苦的事情之一，就是获取你的 API 凭证和密钥。令人震惊的是，他们说：“如果你登录了应用，我们会自动把你的 API 凭证放进例子里，所以你在学习他们的 API 时，只需要复制粘贴一次。“

例子十：Wufoo 的 API 发布活动

当 Wufoo 想要发布我们 API 的第三版时，我们意识到：“好了，终于足够好了，我们想要让人们在此基础上构建东西。” 我们试图弄清楚如何把这件事推向世界，同时带有我们的个性——因为很多人通常会做编程 API 竞赛，送出 iPad 和 iPhone，这让你看起来和所有人一样。所以在我们公司，我们有一个奇怪的价值观：我们的联合创始人是中世纪狂热者，每年公司成立纪念日，我们都会带大家去 Medieval Times（中世纪主题餐厅）。所以我们说，我们必须做那种风格的事情。我们联系了 Armor.com 的人，说：“你们能为我们定制锻造一把战斧吗？” 我们说，如果你赢了我们的编程竞赛，你就赢得这把战斧。结果是，人们想要谈论这件事。人们想要说他们在做这件事，因为他们想要说：“我在为一把武器编程。”

很酷的是，我们收到了超过 25 个不同的应用，质量和数量都是我们在预算和时间内花钱请人做不出来的。我们拿到了 iPhone 应用、Android 应用、WordPress 插件——而我们做的，只是改变了人们讲述他们与我们的一个服务互动的起源故事的方式。

我简而言之，你们应该订阅 Little Big Details。它基本上是大量软件截图，展示了那些做对了的公司，以及他们对用户和客户的用心。

七、婚姻隐喻：长期关系与 Gottman 的研究

当我们谈到长期关系或婚姻时，我们最终需要读的唯一研究是 John Gottman 做的那些。

他是西雅图的一位婚姻研究者，曾经出现在《美国生活》（This American Life）和马尔科姆·格拉德威尔（Malcolm Gladwell）的书中。他有一个有趣的聚会把戏：他可以看一对夫妻就某个问题争吵的录像带 15 分钟，然后以 85% 的准确率预测这对夫妻四年后是还在一起还是会离婚。如果他把录像延长到一个小时，并让他们也谈论他们的希望和梦想，这个预测率会上升到 94%。他们把这些同样的录像带展示给婚姻咨询师、成功结婚的夫妻、社会学家、精神科医生、牧师等等，他们以随机概率都无法预测人们是否会在一起。

所以 John Gottman 对长期关系如何运作有着根本性的理解。基本上，我们即使在短期内的争吵方式，也能预示整个系统会变成什么样子。

他最令人惊讶的发现之一：成功结婚的人并不是不吵架。事实证明，每个人都吵架，而且我们都为了完全相同的事情吵架：钱、孩子、性、时间，以及其他（“其他”指的是嫉妒和姻亲）。

把这个带回来，你可以把每一个这些问题，归因到你在打造产品时客户支持中看到的问题：

  • 钱 → 这太贵了，或者我在信用卡上遇到了麻烦。
  • 孩子 → 用户的客户。
  • 性 → 性能，你能撑多久，有多快。
  • 其他 → 我说的嫉妒或姻亲，那就是竞争和合作伙伴关系，那里发生的任何奇怪的事情，人们都会写信给你。

我喜欢用客户支持的视角来思考这个问题的原因是：在每个人的转化漏斗过程中，客户支持是在每一个步骤之间发生的事情；它是人们无法进一步向下转化的原因；它是阻止转化发生的东西。

八、SDD：支持驱动开发

当我们思考所有这些想法并在公司里落地时，我们意识到大家在创办公司或组建工程团队时，有一个很大的问题。那里有一个破损的反馈循环。人们与他们的行为后果是脱节的。 这是大多数公司成立的自然演变的结果，尤其是有技术联合创始人的公司。

发布之前，是极乐、涅槃和机会的时间。你做的没有错的事。在你的手中——你觉得像上帝——你写的每一行代码、每一行代码都感觉完美；对你来说，它是天才。

发布之后发生的事情是，现实降临了，所有其他任务都出现了；我们需要处理的事情。技术联合创始人想做的事情，是回到那个初始状态，所以我们经常看到的是，公司开始把这些让初创公司变得真实的其他事情隔离开来，让别人去做。在我们心中，这些其他任务是低等的，我们让公司里的其他人去做。

所以对我们来说，我们要弄清楚的是：我们如何改变软件开发，从而注入一些我们讨论得不够的价值观——比如责任、问责、谦逊和谦逊。我们称之为 SDD（Support Driven Development，支持驱动开发）。

这是一种创造高质量软件的方法，但它超级简单；你不需要一堆便利贴。你要做的全部事情就是：让每个人都做客户支持。

你最终修复了反馈循环。打造软件的人，就是支持软件的人。你因此获得了所有美好的好处。

其中之一是支持负责任的开发者和设计师。当人们打造东西时，他们提供最好的支持。我们不是第一个想到这个的人。Paul English 是 Kayak 里这个做法的大力支持者。他所做的事情是：在工程部门中间安装了一部红色客户支持电话，它会一直响，都是客户支持电话。人们经常问他：“你为什么要付工程师 12 万美元或更多的钱，去做你可以用零头请别人做的事情？” 他说：“嗯，在电话响了第二或第三次之后，工程师遇到了同样的问题，他们会停下正在做的事情，修复那个 bug，然后就不再接到关于它的电话了。” 这是一种拥有 QA 的优雅解决方案。

九、Gottman 的”四骑士”：关系的四大警告信号

John Gottman 谈到我们经常分手的原因，归结为四大原因。它们是警告信号。他称之为**“四骑士”**：

  1. 批评（Criticism）：基本上人们开始关注的，不仅仅是眼前的具体问题，而是包罗万象的问题，比如”你从来不听用户的”或”你从来不为我们考虑”。
  2. 蔑视（Contempt）：有人故意试图侮辱另一个人。
  3. 防御（Defensiveness）：不试图承担责任，或者为他们的行为找借口。
  4. 石墙（Stonewalling）：基本上是关闭自己。

根据 John Gottman 的说法，石墙是我们在关系中能做的最糟糕的事情之一。

很多时候我们在客户支持中不注意这些事情——批评或蔑视。防御，你在公司变老时到处都能看到。但石墙，这是我在初创公司中经常看到发生的事情。你收到一堆客户支持电话，你只是想：“我不需要回答，我不需要回应。” 这种甚至不回复的行为，是你能做的最糟糕的事情之一，它可能是初创公司早期阶段流失的最大原因之一。

十、Wufoo 的客户支持实践

以下是 Wufoo 的客户支持运作方式。

当我们被收购时，系统上大约有 50 万用户，500 万人使用过 Wufoo 表单和报告（无论他们是否知道）。所有这些人的支持，都来自同样的 10 个人。通常每天有一个人专门负责支持，轮班。结果每周大约 400 个问题，也就是大约 800 封邮件。

但我们的响应时间：

  • 上午 9 点到晚上 9 点：7 到 12 分钟
  • 晚上 9 点到午夜：1 小时
  • 周末：不超过 24 小时

我们一直把这个标准扩展到规模很大的时候。

很多人谈论 Airbnb 时经常忘记的是，他们是如何做了这件有趣的事情：他们去纽约，提供专业摄影，创始人会亲自去那里给人们公寓拍照，帮助他们卖得更好——聚焦于转化率的那些故事。但大多数人没有意识到的是，我在 Airbnb 早期见到 Joe 时，他头上一直戴着电话耳机，因为他在不停地处理电话支持。

流失率是一个我们不喜欢谈论的故事。 Airbnb 的增长真正开始加速，是在他们弄清楚如何将容量匹配到需求——或者说匹配到他们支持系统中的电话时。

十一、情绪状态实验

在 Wufoo，我们实际上不断围绕支持做实验，因为我们对此非常着迷。

我们做的一个实验是：我们听到这里有人做了一个分享，说我们需要帮助时的情绪，与我们得到帮助时的内容和反应之间，存在一种脱节，尤其是在线，因为人们看不到那些非语言线索。所以她说，除非网络上有面部识别，否则我们总是会与用户脱节。我们的感觉是：“我们不是面部识别专家，但我们认为有另一种获得同理心的方式。”

所以，作为表单构建者，我们添加了一个下拉菜单，上面写着：“你的情绪状态是什么？” 我们的假设是：没人会填这个；我们以为这会是一个很烂的实验，但看看会怎样。

结果，这个字段的填写率是 75.8%。相比之下，“浏览器类型”下拉字段的填写率是 78.1%。所以人们基本上在告诉我们：“对于我的技术支持问题，我对这个问题的感受，和你弄清楚如何调试它所需的所有技术细节一样重要。”

我们没有按情绪对事情进行优先排序或分诊，所以大多数时候人们没有利用系统。这个结论的一个有趣的副产品是：我们注意到人们开始对我们更友好了。我们回去看数据，做了一些文本分析，意识到当通过书面文字（如电子邮件）与人交流时，只有三种方式可以表现出强烈的情绪：感叹号、脏话，以及全部大写。果然，在这三个指标上，人们在客户支持中与我们交谈的方式都有所下降。一旦人们有了一个简单的情绪出口，就让他们变得更加理性，也让我们的工作变得更加愉快。

十二、直接接触用户 = 更好的软件

另一个很棒的副产品是：当你这样做时，你实际上会打造出更好的软件——好得多的软件。这实际上得到了大量研究的支持。

Jared Spool（User Interface Engineering，这个领域最大的玩家之一）说：我们直接接触用户的时间量，与我们设计变得多好之间，存在直接的相关性。

他说这必须以特定的方式发生。必须是直接接触。不能是有人生成报告或通过图表的方式。你必须以近乎实时的方式与他们互动。必须是至少每六周一次，而且每次至少两小时；否则你的软件会随着时间的推移变得更糟。

我们的开发者——那些在 Wufoo 的人——每周直接或间接接触用户 4 到 8 小时。这样做的结果是：它改变了你打造软件的方式。

十三、知识鸿沟与直觉

Jared Spool 还有另一种谈论我们如何打造产品的方式。

想象一下，这代表了使用你的应用所需的所有知识（PPT 幻灯片）。这是零知识（最左边），这是所需的所有知识（最右边）。这两条线基本上是你与用户的互动。这是他们目前的知识水平（PPT 幻灯片），这是你试图让他们达到的目标水平。两者之间的差距，Spool 称之为**“知识鸿沟”**。

有意思的是，只有两种方法可以修复这个问题。这个差距代表了你的应用有多直观。你要么让用户增加他们的知识，要么减少使用应用所需的知识量。

作为工程师或打造这些产品的人，我们经常想的是：“让我们添加新功能。” 新功能只意味着一件事：让我们增加知识鸿沟。

所以对我们要实际上专注于另一个方向。这意味着我们花了 30% 的工程时间在内部工具上，帮助我们的客户支持。但通常花在帮助人们自助的事情上，比如常见问题、工具提示；比如如果你只点击帮助链接，不是带你去通用的帮助文档页面，而是去最适合你正在做的事情的具体页面。我们一遍又一遍地重新设计我们的文档，不断地做 A/B 测试。我们文档页面的一次迭代，一夜之间将客户支持量减少了 30%。这是那种事情：一夜之间，所有在产品上工作的人，工作量直接减少了 30%。

十四、如果你让每个人都持续做客户支持，会发生什么？

我在最开始谈到，增长是转化率和流失率的函数。这是 Wufoo 前五年的增长曲线（PPT 幻灯片）。有意思的是，我们在广告或营销上没有花一分钱；所有增长都是通过口碑完成的。新用户和降级用户之间的交互是这样的（PPT 幻灯片）。要让它起作用，那个差距如此微小。

很多人不断忘记的是：转化率提高 1%，和流失率降低 1%，对增长的作用是完全相同的。 然而，后者实际上更容易做到，也更便宜。很多时候我们忽略了这一点，直到很晚的阶段，而且我们通常让我们的 B 团队来做这些项目和服务。

这实际上不是我们在 Wufoo 大部分时间追踪的图表之一，甚至不是我最自豪的那个。这个才是我最自豪的，因为即使我们有这条漂亮、厉害的增长曲线，正是这个让我们能够扩展、保持公司小规模、并拥有很棒的文化。而这需要做很多这些事情来帮助人们做他们需要做的事情。

十五、不断注入能量：Wufoo 提醒系统

John Gottman 注意到，关系中有一种不同类型的行为，以及人们为什么离婚。基本上有一小部分人，在一起 10 到 15 年后突然离婚。其他指标都不会显示这会发生在他们身上。他翻看数据，意识到：“哦，没有激情，这些人之间没有火花。”

当涉及到关系时，它们有点遵循热力学第二定律：在一个封闭的能量系统中，事物倾向于耗尽，所以你必须不断地把能量和努力放回去。

很多人认为在产品和公司中”展示我在乎你”的方式，是通过创建博客或制作新闻通讯。问题是，我们看看这些比率，基本上只有很小百分比的活跃用户，他们中的大多数人根本不知道我们在为他们做的那些很棒的事情。

所以我们打造了一个新工具，叫做 Wufoo Alert System（Wufoo 提醒系统）。它允许我们为我们的用户，时间戳标记我们打造的每一个新功能。每次他们登录时，我们会看他们的登录时间（或上次登录时间）与新功能的实施时间之间的差异，然后他们会看到这条消息：

“嘿，自从你离开后，Wufoo 为你做了所有这些很棒的事情。”

毫无疑问，这是我每次出去和用户交谈时听到的被谈论最多的功能。他们会说这样的话：“兄弟，我超爱那个’自从你离开后’的东西。虽然我每个月付的钱一样，但你们几乎每周都在为我做些什么。这太棒了；这让我觉得我在获得最大价值。“

十六、写感谢卡：谦逊与感恩

我们做的另一件事，除了让每个人都支持那些给他们发工资的人，还让他们说”谢谢”。这在很大程度上归功于我们在方程式中注入了谦逊和谦逊。

每周五，我们会聚在一起，给我们的用户写简单的手写感谢卡。

我知道有很多人不会对面做这件事感到兴奋；但这是一个产生所有不同的仪式，它让团队非常紧密，并在他们真正关心的事情上工作。他们不断地知道使命是为了什么，以及我们为什么做我们所做的事情。这些不是花哨的感谢卡；它们只是索引卡上的简单手写东西，我们塞进一张贴纸，在前面贴一只恐龙。

有意思的是，我们开始这个做法，是 Wufoo 早期的结果。Chris、Ryan 和我当时在讨论，我们要做什么来在圣诞节前后向用户展示我们欣赏他们。Chris 想出了这个主意：他说：“嘿，几年前我妈妈让我给所有亲戚写感谢信，感谢他们的圣诞礼物，我真的不喜欢做这件事，但第二年我所有的礼物都超级好……所以我觉得我们应该为我们的企业试试这个，看看会怎样。”

所以第一年，我们给所有用户写了手写圣诞卡。第二年到了，只有三个联合创始人，我们有太多客户了。我们在想：“我们要完蛋了；我们不知道要做什么。” 嗯，我们读了一本叫《The Ultimate Question》的书，里面谈到专注于你最赚钱的用户；如果你照顾好他们，事情就会好起来。所以我们想：“这会起作用，这是可扩展的。” 基本上我们只给我们的付费最高的客户写信。

第二年的一月到了，我们一个长期的忠实用户写信给我们。他基本上说：“嘿，兄弟，我真的很喜欢你们第一年寄给我的圣诞卡，我只是想让你们知道，我还没收到我的第二张卡，我在期待它；我知道你们没忘记我。非常感谢。”

所以我们想：操。

超越期望的最好方法，是从一开始就不设任何期望；我们处于这种困境中。我们想了一会儿之后决定的是：我们不能只一年做一次；这需要成为每周都发生的事情。即使我们永远追不上所有的客户，只是做这件事的做法，就会产生所有不同。

十七、市场领导者的三种路径

我谈了很多关于”爱来爱去、触感触感”的东西，我认为很多工程师不喜欢经常思考这些，所以我以硬商业数据或研究结束。

《哈佛商业评论》几年前发表了一篇文章，作者是 Michael Treacy 和 Fred Wiersema，他们在里面谈到了市场领导者的准则。他们说只有三种方式可以实现市场主导地位，取决于你想如何实现那种市场主导地位，你必须以非常特定的方式组织你的公司：

  1. 最优价格（Best Price）：你专注于物流，比如沃尔玛和亚马逊。
  2. 最优产品（Best Product）：你专注于研发，苹果通常是这方面的典型例子。
  3. 最优整体解决方案（Best Overall Solution）：关于与客户亲近。这是你看到所有奢侈品牌遵循的路径，以及酒店业。

我喜欢这条通往市场主导地位的路径的是：第三者是唯一一个每个人都可以在公司任何阶段做的事情。它几乎不需要钱来开始。它通常只需要一点谦逊和一些礼貌。 结果，你可以实现与你市场中任何其他的人一样的成功。

以上就是我要说的，非常感谢大家。

十八、问答环节

Q：如果你有一个有很多不同类型用户的产品，怎么办？你如何打造一个所有用户都热爱的产品？

A： 这里有一条有趣的细线。我通常告诉人们的是：专注于那些最狂热的人，尤其是在早期阶段。 无论它会在哪个利基市场，那就是我要完全专注的地方。

我认为 Pinterest 的 Ben Silbermann 是从设计博主开始的。为他们量身定制你的东西，最终你会弄清楚吸引很多其他人的普遍价值观。所以一次只从一个开始。

你们在上面看到的很多例子，很多公司犯的错误是认为”哦，我只要让我的应用有趣就行了。” 幽默是非常难做到的。 当你想要追求机智的东西时，你必须先把功能性做对。就像日本的质量。如果你没有 atarimae（理所当然的质量），不要试图做任何机智的事情，因为它会适得其反。

所以，我们在 Wufoo 的首要焦点，毫无疑问，是让一切尽可能容易使用；其他一切都只是润色。

Q：如何平衡对产品的痴迷与公司所需的所有其他技能，比如营销、品牌等？

A： 如果你在做产品，你应该始终有这个反面——你在与用户交谈。在 Wufoo 内部，我们让人们与用户交谈的方式是通过客户支持。他们 firsthand 看到功能是否有效，而且它影响了公司里的每个人，因为每个人都有客户支持轮班，所以他们有社交动机让一切运作。

你不应该有任何时候只专注于产品。 你应该始终有时间做产品，然后看看用户对你说了什么——就像持续的虚拟反馈。所以当你没有那个的时候要小心。

关于营销和销售，我的感觉是：营销和销售是你因为没有让你的产品令人注目而付出的税。 口碑是最容易的增长方式，这是很多伟大公司增长的方式。弄清楚如何拥有一个人们想要谈论的关于你的产品的故事，让他们在晚餐桌上成为最有趣的那个人。然后那个人就是你的销售人员。那个人就是你的销售力量。

Q：当用户有很多不同的方向要走时，你如何做产品决策并与工程团队沟通？

A： 我们只是看客户支持，这真的很容易，因为你会看到人们遇到最多麻烦的事情。

你会不可避免地收到功能请求。无论你的产品或应用中有什么开口，人们都会把功能请求塞进去，所以你会知道他们想要什么。你作为产品经理和工程师的工作，不仅仅是按照他们说的做，因为那样你只会成为奴隶。 你必须弄清楚并解决他们真正想要的东西，那个深层的根本原因。

事情是，如果每个人都想要一个不同的方向，那么最终有人会弄清楚。但还有，把每个小想法做成最小版本，构建时间不超过 1 到 2 周，这样你就可以尝试看看什么有效、什么无效。拥有需要大量时间才能弄清楚的多重产品方向是危险的。

Q：你能讲讲 Wufoo 的”King for a Day”（一日国王）的故事吗，那个东西是怎么好的？

A： 好的，我不喜欢黑客马拉松。我认为它们在公司内部做的那些，有点烂，因为你花了 48 小时非常努力地做一些你非常热衷的事情，其中 99% 永远不会投入生产。这超级令人伤心。

所以我们想出了一个叫”King for a Day”的主意。它在周末运作。它的运作方式是：公司里有人被随机抽中，他们成为国王。国王可以告诉其他所有人产品在做什么。 所以所有让他们对 Wufoo 感到困扰的事情，或者他们想要打造的任何其他功能，他们得到了公司里每个人的工程、营销和广告资源，来实现它。当然我们会和他们一起弄清楚我们能在 48 小时内做什么。我们每年做这个一到两次。

这是一个巨大的成功，对士气的提升很大，因为人们最喜欢的事情之一，是做他们认为会产生不同影响的事情，比如”我对应用产生了影响”。所以对我们来说，这是我们划分产品方向时间的一种方式。有时候，为你工作的人，是对产品应该走向何方有最强烈意见的人。这是一个很好地将其民主化的方式，通过轮流来。

Q：你说你们都在家工作，这通常看起来像一场噩梦。你们是如何让它工作的？

A： 我们都在家工作，而且我们都在坦帕湾地区周围工作。我们会允许任何人在任何地方工作，但通常当我们试图招募他们并见到我们的团队时，他们通常决定搬到这里。

远程工作尤其棘手。很多人喜欢把它浪漫化，尤其是作为员工的人，但问题是：办公室给你很多好处和效率，现在当你有远程工作时，你必须补偿这些。 但远程工作也有这些效率。例如，我不必担心我的员工每天损失两个小时在通勤上。

所以我们必须做的最大事情，对于远程工作，是尊重人们的时间。我们设置的方式是，我们在 Wufoo 实际上有一个 4.5 天工作周：周五半天用于所有会议和东西。我们说，没有商务会议，没有与外部各方的交谈。它们必须在周五、在那个半天上完成；它们不能在一周的中间完成。然后还有一天，每个人都专门做客户支持。所以我们公司里的每个人，实际上每周只有三天来实际构建和他们正在做的任何事情。

但我实际上坚信，如果你有三个完整的天，每天 8 到 10 小时，当你只专注于你需要构建的东西时，你可以完成大量的狗屎。所以，我们说的是，在这三天期间，你必须尊重每个人的时间。

我们想出的是 15 分钟规则。你可以和某人聊天或打电话，但它不能超过 15 分钟。所以如果你有某个复杂的问题你无法弄清楚，在 15 分钟时你要立即把那个项目搁置，让我们在周五讨论它。你继续列表上的下一个项目。

我会说 90% 的时间，那个项目永远不会在周五被提出来，因为通常发生的事情是人们会睡一觉，然后你会神奇地说：“嘿，我找到了解决方案！“或者”嘿，那根本不是什么大问题。” 公司内部的大多数问题，不需要实时或立即解决。唯一的事情是网站宕机或支付不工作的时候。除此之外的一切，都是奢侈品。

所以尽可能专注于你的优先事项，结果我们的 10 人团队做的事情，比很多很多其他公司多得多。

但这需要额外的工作来让远程工作发生。我们是一个极其自律的团队，我不得不说，YC 中没有很多公司能够复制我们所做的事情。我认为 YC 中只有两家公司能够复制我们的纪律风格。 这需要以非常不同的方式做更多的工作。而且通常允许你在生产力方面更懒一点，关于所有这些事情。

Q：作为管理者，我们如何为员工建立问责制？

A： 我们在发布九个月后就盈利了，所以我们有利润分享，这让激励相当简单和清晰。这将是我们的任何奖金池的倍数，绩效衡量将基于他们在客户支持中的表现、他们在那里的职责，以及他们说什么他们想要完成。

我不喜欢流程，我不喜欢很多帮助人们提高生产力的工具，所以我们用来帮助人们管理项目的唯一东西，是一个待办事项列表。它是一个简单的文本文件，我们在 Dropbox 账户中共享。每个人都有他们的名字在上面，你每次有人更新待办事项列表上的东西时都能看到。

我们说的是：每天晚上，你写下那天你做的一切，周五我们 just go over：“这是你上周说你要做的事情；这是你实际完成的。眼前的问题是什么？” 这超级简单。它创造了这种很好的书面轨迹来处理事情，我不必担心管理他们。他们为自己想要被评估的基调定调。

对于善于做他们做的事情的人，这非常非常有效。当你实际上有问题时，解雇人非常容易。我很幸运不必在 Wufoo 解雇任何人，但我们能够非常非常快地纠正每个人的行为，因为我们只是看着这个并评估问题：“看，这是行为模式。你一直在最后一分钟做你的工作，等等。这是你提供给我们的证据；我们要做的就是把它描述回给你。” 因为公司里的每个人都看到它，有社会压力被放进来帮助让这一切发生。

Q：你如何招聘能够远程工作并以这种方式工作的人？

A： 相当容易，你让他们为你做一个副项目。所以你外包给他们，让他们远程工作。通常我喜欢让他们做的项目是大约一个月长，这样你可以很好地了解人们如何管理自己和做事情。这一直是第一个评估；我们从来不通过面试来做事情。

我们要筛选的另一件事，是他们在客户支持方面的能力，因为不是每个工程师都有那些同理心技能来处理那种压力。所以有时候我会让人们在面试中给我写”分手”信，给他们 15 分钟来写。这样你就可以很好地了解他们的写作能力，因为你在客户支持中做的 90% 的事情，是告诉客户坏消息，比如”我们不支持那个功能，抱歉”，或”不，那行不通”，或”那将不可用”。

Q：在你的公司里，有没有什么技巧或实验没有成功？

A： 好的，我来谈一个。

我们早期做的一件事情，试图激励我们自己——我们理解 crunch mode（赶工模式）的想法，这对人们非常糟糕。比如，如果你在做订阅业务，你需要人们持续很长时间，而在视频游戏中，他们经常让人们为了特定时间 crunch，他们有多个冲刺。大多数时候，截止日期会变得超级令人筋疲力尽。你可能会获得生产力的增加，但你需要的恢复，总是大于你获得的生产力。在一个你需要每个人做客户支持、处于他们的最佳状态、并不断推出功能的公司里，你没有时间恢复。

所以我们当时想，我们想要把公司假期构建到 Wufoo 的运作方式中，每年奖励我们的用户。所以我们想，如果假期是内置的用于恢复，我们可以有一个 crunch 期间在假期之前设置，只做客户支持，那将随着人们扩展。所以我们做第一个 crunch mode 的方式是：它只是三个联合创始人之间的事情，我们让每个人画一个 10 项的待办事项列表，这将是相当地激进的。第一个 through 他们的七项的人会赢，最后一个 through 他们的七项的人，会成为我们所说的”Trip Bitch（旅行苦力）“。Trip Bitch 意味着你帮别人拿行李，并在公司假期时给别人拿饮料。

我们做了那个，在那个期间，每个人都很兴奋。赢家还可以选择下一个公司假期。但突然之间，Ryan 基本上低估了他列表上的项目的难度，很快意识到”我要他妈的输了”，他就放弃了。所以 crunch mode，对他来说变成了 blah mode，因为他知道他会输，变得相当气馁。

结果我们决定不再以类似的方式再做一次。好主意，我们喜欢谈论，但这是我们再也不会做的那个。
